写一个多Agent辩论系统的过程记录

2026-08-05

想法

Agent是一个很火的方向。之前做的几个项目(Raft KV store、mini-sql)都是传统CS方向, 想做点AI相关的。LLM本身是黑盒, 但Agent=LLM+自主决策, 这个组合很有意思。

辩论系统是最简单的多Agent场景: 三个role各说各的, 不需要外部tool, 不需要RAG, 不需要复杂planning。纯prompt engineering就能跑。

Day 1: 核心架构

先搭了四个文件: llm.py (LLM client), agent.py (Agent class + role config), debate.py (coordinator), main.py (CLI entry)。

LLM client用urllib直连OpenAI compatible API, 不依赖任何第三方SDK。这个决策省了很多pip install的麻烦 - 只要环境变量设置了API key就能跑。

Agent class的设计比较简单: 每个Agent有自己的system prompt(定义role personality)和conversation history。hear()听别人发言, speak()生成自己的发言。

Coordinator控制发言顺序: proposer -> critic -> proposer -> critic -> judge。默认两轮, --rounds参数可以调。

写了mock_llm.py, 用预设回复模拟LLM输出, 这样不需要API key也能跑demo。这个在调试时特别有用, 不用每次改代码都花钱调API。

Day 2: 自定义role和统计

加了两个功能: JSON配置文件和debate统计。

config.py让用户可以自定义三个role的personality。比如可以把critic换成安全专家, 从security角度挑刺。配置文件是JSON格式, 只写两个role也行, 第三个自动补默认值。

stats.py追踪整场debate的数据: 每个speaker的发言次数、总字数、平均字数、verdict长度、总耗时。这些数据存下来以后可以分析不同prompt的效果。

技术要点

  • 纯标准库(urllib + json + argparse), 零pip依赖 - 这个对展示项目很重要, 谁都能clone下来跑
  • OpenAI compatible API - 不仅支持OpenAI, 任何兼容的API(vLLM, Ollama, 国内各种proxy)都能用
  • system prompt engineering - role personality完全通过prompt控制, 没有hardcode行为逻辑
  • mock模式 - 预设回复模板, 演示效果不需要花API费用

还可以做什么

  • streaming输出 - 目前是等LLM全部返回再显示, 改成实时流式输出体验会好很多
  • 更多debate模式 - 除了三角色辩论, 还可以做panel discussion(N个专家+1个主持人)
  • API integration - 让Agent在辩论时可以调用搜索工具查实时数据, 真正变成Agent
