用 C 语言写一个 HTTP 服务器是什么体验

2026-07-15

起因

这学期上了计算机网络，TCP 三次握手四次挥手背得滚瓜烂熟，但除了用浏览器发请求之外从没真的写过 socket 代码。期末考完后就想试试——用 C 从零写一个能跑起来的 HTTP 服务器。

第一阶段: Hello TCP

先照着 CSAPP 第11章抄了一个最简单的 echo server：

int listenfd = socket(AF_INET, SOCK_STREAM, 0);
bind(listenfd, (struct sockaddr*)&addr, sizeof(addr));
listen(listenfd, 10);
int connfd = accept(listenfd, NULL, NULL);

跑起来后用浏览器访问 localhost:8080……什么都没有。原来浏览器发的是 HTTP 请求，我回的是纯文本 "hello"，它根本不认识。

第二阶段: 解析 HTTP

浏览器发的第一行大概长这样：

GET /index.html HTTP/1.1\r\n

所以要解析出方法(GET)、路径(/index.html)、版本(1.1)。然后是 headers，每行都是 Key: Value\r\n 格式，直到空行 \r\n\r\n 分隔 headers 和 body。

我在 http.c 里写了一个状态机式的解析器——逐行读，遇到空行就停。解析完了按格式构造响应报文，这步搞了两天。

第三阶段: 多线程

单线程跑通后兴高采烈地用浏览器测试……卡住了。排查了半天发现 Chrome 会同时发两个请求(主页 + favicon.ico)，而我单线程的 accept 循环一次只能处理一个。

解决方案: 每个连接创建一个线程：

pthread_t tid;
pthread_create(&tid, NULL, handle_client, arg);
pthread_detach(tid);

问题是请求多了线程数爆炸。虽然 pthread_detach 会自动回收，但创建/销毁开销很大。

第四阶段: 线程池

看了生产者-消费者模型，写了个简易线程池：

typedef struct {
    pthread_t workers[8];
    task_t    queue[64];
    int       front, rear, count;
    pthread_mutex_t lock;
    pthread_cond_t  not_empty;
    pthread_cond_t  not_full;
} threadpool_t;

主线程 accept 后把 fd 扔进队列，worker 线程从队列取任务处理。这里踩的最大坑是 pthread_cond_wait 的虚假唤醒——文档说 wait 可能在没有 signal 的情况下返回，所以必须用 while 而不是 if 来检查条件。

总结

  • socket 编程比课上讲的复杂——SO_REUSEADDR、send 不一定发完、网络字节序……都是书上不提但实际会遇到的
  • HTTP 协议本身的解析不复杂，繁琐的是各种错误处理和边界条件
  • 线程池核心就是 mutex+cond 的生产者-消费者模型
  • C 语言写网络程序的最大痛点是内存管理，忘记一个 free 就内存泄漏
