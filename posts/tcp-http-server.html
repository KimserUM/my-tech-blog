Writing an HTTP Server in C

2026-07-15

Why

Networking course covered TCP handshakes, but never wrote socket code. After finals, wanted to try building a real HTTP server from scratch.

Phase 1: Hello TCP

Started with CSAPP chapter 11 echo server:

int listenfd = socket(AF_INET, SOCK_STREAM, 0);
bind(listenfd, (struct sockaddr*)&addr, sizeof(addr));
listen(listenfd, 10);
int connfd = accept(listenfd, NULL, NULL);

Browser visited localhost:8080, got "hello". Didn't understand it — browsers expect valid HTTP responses, not raw text.

Phase 2: Parsing HTTP

Browser sends:

GET /index.html HTTP/1.1\r\n

Parsed method (GET), path (/index.html), version (1.1). Headers: Key: Value\r\n format until empty line \r\n\r\n. Wrote a state machine in http.c.

Phase 3: Multithreading

Single-thread worked until Chrome sent two requests at once (page + favicon.ico). accept() blocked on the first while the second queued. Added pthread per connection:

pthread_t tid;
pthread_create(&tid, NULL, handle_client, arg);
pthread_detach(tid);

Worked, but wasteful — creating/destroying threads for every request.

Phase 4: Thread pool

Producer-consumer model: main thread (producer) drops fds into circular queue after accept. Worker threads (consumers) pop and process. mutex protects queue state, cond signals when queue is non-empty/non-full.

Key bug: pthread_cond_wait can wake spuriously — must use while loop, not if, when checking the condition.

Summary

  • Socket programming has details books skip: SO_REUSEADDR, partial send(), network byte order
  • HTTP parsing is straightforward; edge cases are the hard part
  • Thread pool core is mutex + cond producer-consumer
  • C networking means manual memory management — forgetting free = leak
