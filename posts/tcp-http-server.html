用C写一个HTTP服务器是什么体验

2026-07-15 · 约5分钟

起因

这学期上计网，TCP三次握手四次挥手背得滚瓜烂熟，但除了用浏览器发HTTP请求之外从没真的写过socket代码。 期末考完后就想试试——如果让我从零写一个能跑起来的HTTP服务器，会怎样？

第一阶段: Hello TCP

先写个最简单的echo server。照着CSAPP第11章的代码抄了一遍:

int listenfd = socket(AF_INET, SOCK_STREAM, 0);
bind(listenfd, (struct sockaddr*)&addr, sizeof(addr));
listen(listenfd, 10);
int connfd = accept(listenfd, NULL, NULL);

跑起来后拿浏览器访问localhost:8080……什么都没有。原来浏览器发的是HTTP请求，我回的是纯文本"hello"，它不认识。

第二阶段: 解析HTTP

浏览器发的第一行大概是这样的:

GET /index.html HTTP/1.1\r\n

所以要解析出来方法(GET)、路径(/index.html)、版本(1.1)。

然后是headers，每行都是Key: Value\r\n格式，直到空行\r\n\r\n分隔headers和body。

我在http.c里写了一个状态机式的解析器——逐行读，到空行就停。解析完了构造响应报文，格式跟请求差不多。这步搞了两天。

第三阶段: 多线程

单线程跑通后兴高采烈地用浏览器测试……卡住了。排查了半天发现Chrome会同时发两个请求(主页+ favicon.ico)，而我单线程的accept循环一次只能处理一个。

解决方案: 每个连接创建一个线程:

pthread_t tid;
pthread_create(&tid, NULL, handle_client, arg);
pthread_detach(tid);

但这有个问题: 请求多了线程数爆炸（虽然pthread_detach会自动回收，但创建/销毁开销很大）。

第四阶段: 线程池

看了生产者-消费者模型，写了个简易线程池:

typedef struct {
    pthread_t workers[8];
    task_t queue[64];
    int front, rear, count;
    pthread_mutex_t lock;
    pthread_cond_t not_empty;
    pthread_cond_t not_full;
} threadpool_t;

主线程accept后把fd扔进队列，worker线程从队列取任务处理。关键是用mutex+cond保证线程安全。

这里踩的最大坑是pthread_cond_wait的虚假唤醒——文档说wait可能在没有signal的情况下返回，所以必须用while而不是if来检查条件。

总结

  • socket编程比课上讲的复杂——SO_REUSEADDR、send不一定发完、网络字节序……都是书上不提但实际会遇到的
  • HTTP协议本身的解析不复杂，繁琐的是各种错误处理和边界条件
  • 线程池比想象的简单，核心就是mutex+cond的生产者-消费者模型
  • C语言写网络程序的最大痛点是内存管理，忘记一个free就内存泄漏
