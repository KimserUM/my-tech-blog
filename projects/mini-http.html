mini-http-server

C | socket | pthread | thread pool | ~1200 lines | 2026.06-07

What it does

A from-scratch HTTP/1.1 server written in C. Listens on a TCP port, parses HTTP requests, serves static files, and exposes a few JSON API endpoints.

Architecture

main.c  - entry point, signal handling
server.c - TCP socket (socket/bind/listen/accept), thread pool dispatch
http.c   - HTTP request parsing, response building
threadpool.c - producer-consumer thread pool (mutex + cond)

Key implementation details

HTTP parsing

Manual state machine. First line parsed with sscanf to extract method, path, version. Header lines split on the first colon. Body separated by the double CRLF marker. Content-Length header used to determine body size.

Thread pool

Producer-consumer model with a circular queue. Main thread (producer) drops client fds into the queue after accept(). Worker threads (consumers) pop tasks and process them. pthread_mutex_t protects the queue, pthread_cond_t signals when queue is non-empty or non-full.

typedef struct {
    pthread_t workers[MAX_WORKERS];
    task_t    queue[MAX_QUEUE];
    int       front, rear, count;
    pthread_mutex_t lock;
    pthread_cond_t  not_empty;
    pthread_cond_t  not_full;
    int       running;
} threadpool_t;

Keep-Alive

If the client sends Connection: keep-alive, the server keeps the socket open and reads multiple requests in a loop (max 50 per connection, 5s timeout). Connection: close header signals the last response.

API endpoints

  • GET /api/time — server timestamp
  • GET /api/stats — thread pool status
  • GET /api/headers — echo parsed request info
  • POST /api/echo — echo POST body
  • POST /api/upload — simple file upload via multipart/form-data

Problems solved

  • Port reuse: SO_REUSEADDR to avoid TIME_WAIT blocking restarts
  • Browser double-request: Chrome requests /favicon.ico alongside the main page. Single-threaded version deadlocked until pthread was added.
  • send() partial writes: send() return value checked, loop if needed
  • Binary file serving: fopen with "rb" on Windows to avoid CRLF corruption of images
  • Path traversal: is_safe_path() blocks ".." in URL paths

What could be better

  • epoll instead of thread-per-connection for higher concurrency
  • Proper HTTP/1.1 pipelining
  • Chunked transfer encoding
  • TLS/HTTPS support
