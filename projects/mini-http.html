mini-http-server

C 语言 | socket | pthread | 线程池 | ~1200行 | 2026.06-07

项目简介

用 C 语言从零实现的 HTTP/1.1 服务器。监听 TCP 端口，解析 HTTP 请求，提供静态文件服务和几个 JSON API 接口。写这个项目是为了把计网课上学到的 TCP/IP、HTTP 协议真正用代码实现一遍。

架构 / Architecture

main.c        - 入口，信号处理
server.c      - TCP socket 监听，线程池分发
http.c        - HTTP 请求解析，响应构造
threadpool.c  - 生产者-消费者线程池 (mutex + cond)

HTTP 解析

手写状态机解析 HTTP 报文。第一行用 sscanf 提取方法、路径、版本。headers 按冒号切割，body 通过 Content-Length 确定长度，\r\n\r\n 分隔 headers 和 body。

线程池

生产者-消费者模型 + 循环队列。主线程(生产者) accept 之后把 fd 丢进队列，worker 线程(消费者)取任务处理。

typedef struct {
    pthread_t workers[8];
    task_t    queue[64];
    int       front, rear, count;
    pthread_mutex_t lock;
    pthread_cond_t  not_empty, not_full;
    int       running;
} threadpool_t;

Keep-Alive 长连接

如果客户端发来 Connection: keep-alive，同一个 socket 可以处理多个请求（最多 50 个）。Connection: close 标记最后一个响应。

API 接口

  • GET /api/time — 服务器时间戳
  • GET /api/stats — 线程池状态
  • POST /api/echo — 回显 POST 数据
  • POST /api/upload — multipart/form-data 文件上传

踩坑记录

  • 端口被占用: 没加 SO_REUSEADDR，关了服务器马上重启报错。加上就好了
  • Chrome 发两个请求: 浏览器会同时请求 /favicon.ico，单线程直接卡死
  • send() 不一定发完: 返回值和期望长度不一致时要循环发
  • 图片文件: Windows 下必须 "rb" 打开，不然图片会被 CRLF 搞坏
  • 路径遍历: is_safe_path() 检测 ".." 防止目录穿越攻击
