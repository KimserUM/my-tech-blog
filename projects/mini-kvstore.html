mini-kvstore

Python | Raft consensus | WAL | TCP | ~1500 lines | 2026.07

What it does

A distributed key-value store with Raft-based consensus. Multiple nodes form a cluster, elect a leader, and replicate write operations across all nodes. Reads can be served by any node.

Three-layer architecture

Layer 1: Store (store.py)
  - In-memory dict + WAL (Write-Ahead Log)
  - JSON-line log format for human readability
  - Snapshot-based compaction when log exceeds 10MB
  - Crash recovery: replay WAL on startup

Layer 2: Network (net.py)
  - Custom binary protocol: [4-byte big-endian length][JSON body]
  - TCP with automatic reconnection
  - Async message dispatch via threading

Layer 3: Consensus (raft.py)
  - Leader election with randomized timeouts
  - Log replication via AppendEntries RPC
  - Commit only current-term entries (paper section 5.4.2)

Raft implementation notes

Leader election

Three states: Follower, Candidate, Leader. Each node starts as Follower. If no heartbeat received within election timeout (3-6s randomized), become Candidate, increment term, vote for self, send RequestVote to all peers. Win with majority. Step down if higher term seen.

Log replication

Leader receives client writes, appends to local log, sends AppendEntries to followers. On majority ACK, commit and apply to state machine. Leader tracks nextIndex and matchIndex per follower. On mismatch, decrement nextIndex and retry until convergence.

Safety constraints

  1. Election restriction: candidate's log must be at least as up-to-date as majority
  2. Commit rule: only commit entries from current term (paper 5.4.2)
  3. Term monotonic: never decrease; always step down on higher term

WAL design

{"op": "set", "key": "name", "val": "tom"}
{"op": "del", "key": "temp"}
{"op": "set", "key": "count", "val": 42}

Each line is a JSON record. On crash recovery, load the last snapshot (full state dump), then replay WAL entries added after the snapshot. Corrupted lines (partial writes during crash) are skipped.

CLI usage

# Terminal 1: start node 1
python -m src.server --id node1 --port 8000

# Terminal 2: start node 2, join cluster
python -m src.server --id node2 --port 8001 \
  --peers node1:127.0.0.1:8000

# In the leader terminal:
>> set hello world
>> get hello
>> status

Problems encountered

  • Election split: with 100ms timeout, all 3 nodes became candidates simultaneously. Fixed by increasing to 3-6s.
  • Stale leader: old leader didn't check term on incoming RPCs, continued acting as leader. Fixed by adding term checks to every handler.
  • WAL format: initially used pickle, couldn't debug corrupted logs. Switched to JSON lines.
