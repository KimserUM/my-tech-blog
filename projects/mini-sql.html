mini-sql

Python | 词法分析 | 递归下降解析 | 执行引擎 | ~1100行 | 2026.07-08

项目简介

手写 SQL 解析器和执行引擎。三阶段流水线: 词法分析器将 SQL 文本转为 Token 序列，递归下降解析器构建 AST，执行引擎在内存表中执行 AST。顺便把编译原理复习了一遍。

流水线 / Pipeline

SQL 文本
  -> Tokenizer (手写状态机)
  -> Token 序列
  -> Parser (递归下降)
  -> AST 抽象语法树
  -> Engine (树遍历求值)
  -> 结果

第一阶段: 词法分析

手写有限状态机。状态: 空白(跳过)、数字(连续读取)、单词(读完后查关键字表)、字符串(单引号包围)、操作符(单/双字符)。注释(--)跳过。

第二阶段: 语法分析

递归下降。每个语法规则对应一个解析函数。运算符优先级通过函数调用层次实现:

parse_expr -> parse_or -> parse_and -> parse_cmp -> parse_atom

parse_or 调用 parse_and，在 OR 上循环。parse_and 调用 parse_cmp，在 AND 上循环。优先级自然正确，不需要显式的优先级表。

第三阶段: 执行引擎

表数据: dict of dicts(每行一个 dict)。WHERE 求值递归遍历 AST 节点，ColumnRef 从当前行取值，BinaryOp 左右子树求值后运算。ORDER BY 用 (type_priority, value) 元组包装排序键，解决不同类型比较时 TypeError 的问题。

支持的 SQL

CREATE TABLE users (id INT, name STRING, age INT);
INSERT INTO users (id, name, age) VALUES (1, 'tom', 20);
SELECT * FROM users WHERE age >= 20;
SELECT name FROM users ORDER BY age DESC LIMIT 5;
DELETE FROM users WHERE id = 3;

踩坑

  • 正则 tokenizer 在字符串里的逗号上翻车，换手写状态机
  • AND/OR 优先级: 一开始当同级处理导致语义错误，拆成 parse_or/parse_and
  • ORDER BY + NULL: 不同类型直接比较会 TypeError，用(type_group, value)解决
