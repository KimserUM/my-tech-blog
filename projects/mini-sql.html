mini-sql

Python | tokenizer | recursive descent parser | engine | ~1100 lines | 2026.07-08

What it does

A SQL database engine: lexer converts SQL to tokens, parser builds an AST, engine executes on in-memory tables.

Pipeline

SQL -> Tokenizer (hand-written FSM) -> Parser (recursive descent)
    -> AST -> Engine (tree-walk) -> Result

Tokenizer

Hand-written FSM. States: whitespace, number, word (keyword table lookup), string, operator. Comments (--) skipped.

Parser

Recursive descent. Operator precedence via call hierarchy:

parse_expr -> parse_or -> parse_and -> parse_cmp -> parse_atom

Engine

Tables as dict of dicts. WHERE walks AST: ColumnRef gets row value, Literal returns constant, BinaryOp recurses then applies operator. ORDER BY uses (type_group, value) tuples for safe comparison. Type conversion at INSERT time.

Supported SQL

CREATE TABLE users (id INT, name STRING, age INT);
INSERT INTO users VALUES (1, 'tom', 20);
SELECT * FROM users WHERE age >= 20;
SELECT name FROM users ORDER BY age DESC LIMIT 5;
DELETE FROM users WHERE id = 3;

Problems

  • Regex tokenizer broke on string commas, replaced with FSM
  • AND/OR precedence wrong, split into parse_or/parse_and
  • NULL in ORDER BY: (type_group, value) tuple sort keys
